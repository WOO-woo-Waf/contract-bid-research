# 合同审核与智能投标调研总览

形成日期：2026-08-04

## 背景

合同审核和投标文件编制都属于“长文档、高风险、强证据、多人协作”任务。公众号文章提供了产品线索，但宣传功能、源码能力、许可证和可生产化程度必须分开判断。本次调研以用户提供的四篇文章为入口，完成源码拉取、固定提交、代码级核验、最小构建验证、任务定义和二次开发路线设计。

## 目标

1. 建立可持续更新的调研仓库，而不是一次性聊天结论。
2. 定义合同审核和智能投标的任务边界、输入输出与评测口径。
3. 优先复用成熟开源项目和已有 MinerU 解析基础设施。
4. 区分文章声称、README 声称、源码确认和运行验证四个证据等级。
5. 为后续业务 MVP 留下许可、隐私、安全和人工复核边界。

## 非目标

- 本阶段不替代律师、法务负责人或投标负责人作最终判断。
- 不重复建设 OCR、PDF/Office 解析、解析队列或模型部署。
- 不把未经核验的区块链、联邦学习、混沌工程等宣传能力纳入架构。
- 不把英文公开数据集上的效果直接等同于中文合同生产效果。
- 不推送任何远程仓库，也不上传客户合同或标书。

## 证据方法

| 等级 | 含义 | 本次示例 |
|---|---|---|
| E0 | 用户/文章声称，尚未独立核验 | AI LegalComp 的区块链、联邦学习、多语言审查 |
| E1 | 仓库 README 或项目文档声称 | VerveDocs 多格式协作、易标十万字成本 |
| E2 | 固定提交的代码中存在明确实现 | 易标技术方案任务、查重、废标检查、远程埋点 |
| E3 | 本机完成构建或接口实测 | 易标 Renderer 构建通过、Verve Core 构建通过、演示站返回 200 |

所有正式结论至少标明证据层级。法律结论还必须保存来源法规版本和人工审批记录。

## 已有基础设施决策

用户确认 `/root/dev/mineru-api-docker-upgrade` 已完成 MinerU 3.4.4 部署。其现有设计已经明确：

- PDF、图片、DOCX、PPTX、XLSX 统一由 MinerU 主链路处理。
- 业务主数据应是版本化 Canonical Document JSON，Markdown 只是派生展示/算法输入。
- 来源锚点保存页码、bbox、段落/run、slide/shape、sheet/cell 等定位语义。
- `/v1/process`、`/tasks`、`/file_parse` 提供兼容、异步和同步接口。
- Docling 只适合长尾格式或回归对照，不应另建生产解析服务。

本次远程 `readyz/health/docs` 严格 TLS 探测被自签名证书拒绝；没有禁用证书校验。部署状态以用户确认为准，证书链应在正式集成验收时修复或通过受信任内网 CA 配置。

## 推荐总体方案

```text
合同/招标文件
    ↓
现有 MinerU 3.4.4 + Canonical Document JSON + SourceAnchor
    ↓
领域结构化层
    ├── 合同：条款、主体、义务、事实、风险、规则符合性
    └── 投标：需求、评分项、废标项、全局事实、响应矩阵
    ↓
规则引擎 + 检索/NLI/LLM + 确定性校验
    ↓
证据图（每个结论/生成主张绑定原文锚点和规则版本）
    ↓
人工审核工作流
    ├── OpenContracts：语料、标注、抽取、权限、引用图
    ├── VerveDocs：Word 内容编辑/协作候选
    └── 易标：投标工作流参考或隔离式 AGPL 组件
    ↓
审查报告 / 修订建议 / 合规矩阵 / DOCX 标书
```

## 核心判断

1. **合同方向首选 OpenContracts 作平台基座。** 它是 MIT，已有文档语料、精确标注、结构化抽取、权限、引用图、GraphQL/MCP 和 Docling/文本解析适配；应接入现有 MinerU/Canonical JSON，而不是使用它自带解析替换 MinerU。
2. **投标方向借鉴易标，但谨慎直接嵌入。** 技术方案、全局事实、知识库、查重、废标检查和 Word 导出有实际代码；商务标、标讯、AI 评标、图片知识库等仍未完成。AGPL-3.0-only 与 NOTICE 会影响闭源商业产品，应选择独立部署并履约，或只借鉴任务设计并自主实现。
3. **VerveDocs 是编辑器，不是合同审核系统。** MIT 和模块化很适合二开 Word 编辑体验，但当前仓库缺根 workspace、部分 lockfile 过期、完整版 UI 含 Windows 专属构建依赖，协作认证仅信任客户端自报 userId，必须整改后才能生产使用。
4. **AI LegalComp 暂不进入候选短名单。** 在拿到可审计源码、许可证和可复现部署前，文章中的“完整开源、可商用”以及高级功能均不能采信。
5. **隐私必须按数据流描述，不能只写“本地部署”。** 易标会访问模型 API、MinerU API、远程埋点/公告/许可证/错误上报；只有本地模型、内网解析、遥测关闭、日志脱敏和出站白名单同时成立，合同正文才真正不出域。

## 影响范围

未来业务新增的是领域模型、规则库、证据图、评测集、审核工作流和编辑集成；不新增第二套文档解析平台。需要重点评审的边界是 AGPL 组件隔离、模型/数据集许可、客户数据隔离、人工审批和法规版本管理。

## 风险与约束

- 中文合同和中文招标公开高质量数据不足，必须建设自有匿名化金标集。
- 高召回风险识别会带来误报；关键风险允许多报，但不能让低置信模型自动改合同或做承诺。
- 条款含例外、否定、交叉引用和附件，简单向量检索无法保证完整性。
- Word 高保真编辑/导出应做真实模板回归，不能只看 HTML 预览。
- 公开源码的代码许可证不自动覆盖模型权重、训练数据、字体、图标和第三方服务条款。
